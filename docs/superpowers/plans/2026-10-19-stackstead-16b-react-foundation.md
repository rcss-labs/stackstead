# Stackstead Plan 16b — React foundation (b): primitives, shell, routing, toasts, ⌘K palette

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Plan format:** tasks, names, signatures, test cases and examples only; no code bodies. Implementers write everything test-first.

**Goal:** On top of Plan 16a, build the React application frame that every screen plan (17–22) renders into: the Evolve v2 primitives (CSS Modules, behaviour tests ported from `components.test.ts`), the chassis shell (232px sidebar with live host block, 48px desktop top bar, mobile top bar and bottom tab bar under 760px), toasts, the `⌘K`/`Ctrl+K` command palette fed by the live stores, and React Router 8 routing with every route mapped to a lazy placeholder, the session guards, focus-to-h1, document titles, banners and the unsaved-changes guard exactly as `App.svelte` has them today — with the React entry bundle measured against `ENTRY_BUDGET`.

**Architecture:** `web/src/app/components/` holds the primitives, `web/src/app/shell/` the Sidebar, TopBar, MobileTopBar, TabBar, Toasts, CommandPalette and the pure `palette.ts`, `web/src/app/routes.tsx` the route table with `React.lazy` screens (only the Overview placeholder is eager), `web/src/app/App.tsx` the `BrowserRouter`, guards and banners. Store logic stays in `web/src/lib` and is read through `useStore`: `session`, `live`, `changes`, `stacks`, `toasts` (extended additively with `pending` and `link`), `guard`, `appearance`, `media`, and a new `stores/host.ts` poller for the sidebar host block. `router.ts` gains the pure `safeNext` (moved from `Login.svelte`, which re-exports it) and lends `matchRoute`; React Router owns navigation.

**Tech Stack:** React 19.3.1, react-router 8.4.0 (declarative `BrowserRouter`, `Routes`, `Route`, `Link`, `useNavigate`, `useLocation`, `useParams`, `useSearchParams`), CSS Modules, Vitest + jsdom + @testing-library/react + @testing-library/user-event, TypeScript strict. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-stackstead-react-evolve-v2-design.md` §2.1 (parity list), §4 (anti-goals), §5 (budgets, lazy routes), §6.1–§6.4, §8 "Palette", §9 row 16. README: "Migration requirements", "Identity elements" (LED, chassis sidebar), "Global" (top bar, palette, toasts, mobile, motion), "State" (shell). **Depends on Plan 16a** being merged: `$lib/store`, `useStore`, `tsconfig.app.json`, `app.html`/`vite.app.config.ts`, `build:app`, the tokens and base styles.

## Spec divergences

1. **Unsaved-changes guard without `useBlocker`.** React Router's blocker API needs a data router; in declarative mode the guard is the same link-click capture `App.svelte` uses today (`onClickCapture` on the layout, same exclusions for modifier keys, `target`, `download`, cross-origin and same-URL links) plus the logout path. Back/forward navigation is not guarded, exactly as today.
2. **Running-operation pill text.** The README shows `pull · immich 64%`; the API's `Operation` has no progress. The pill shows `<action> · <stack>` for one running operation and `<n> running` for several (keeps today's `2 running` test), always `role="status"`, spinner while any operation runs.
3. **Host block data.** The README says host values tick "every ~2s from the metrics stream"; there is no host metrics stream (`/api/events` carries container events only). The sidebar polls `GET /api/host` every 10 s while the tab is visible through a new `lib/stores/host.ts` (same rules as `dashboard/controller.ts`), so the overview (Plan 17) can share it. Null sections render `—` and an empty bar.
4. **Nav counts.** The design shows a count on every nav item (stacks, containers, networks, storage size). Only the Stacks count comes from an eager store; Containers/Networks/Storage counts are added by Plans 19/21/22 when their stores exist (the `NavItem.count` prop is in place now).
5. **Versions line and pills.** Today's TopBar Docker/compose pills move into the sidebar user row (`Docker 27.1.1 · compose 2.29.2`, `Docker unavailable`, neutral `Docker` before the first status), keeping the exact strings and the neutral-before-status rule the TopBar tests pin. The top bar keeps breadcrumbs, the running pill and the new `live` pill.
6. **Palette actions.** Lifecycle entries (`Restart <stack>`, `Up <stack>`, `Pull <stack>`) exist for every stack but are listed only once the query is non-empty, so an empty palette stays short (pages, stacks, `New stack`, `Clean up storage`, `Toggle theme`). `Clean up storage` navigates to `/storage` (the cleanup dialog is Plan 21's).
7. **Placeholder screens.** Every route renders a placeholder with the right landmark and `h1` (page name, or the decoded entity param for `/stacks/:name`, `/containers/:name`, `Image <id>`, `Volume <name>`). Login is a minimal working form (labelled Username/Password, `Log in`, calls `login()` and `safeNext`) because the session tests need a real login; Setup is a heading only. Plans 17–22 replace them. App tests that need a real screen (`Container not found`, `Image not found` text, Setup form) are ported in those plans and listed in Task 5.
8. **Mobile breakpoint** is 760px (README) instead of today's 720px; it is the one literal media query (`max-width: 759px`) and the `useIsMobile` hook uses the same string.

## Global Constraints

- Behaviour parity (spec §2.1, §4): routes and query params, `needs-setup → /setup`, `anonymous → /login?next=` with `safeNext`, focus to the new page's `h1` (never on first load, never on a query-only change, never when the page placed focus itself), titles `<Page> · Stackstead` only while authenticated, the four banners, `aria-current="page"`, `aria-pressed` chips, soft-disabled buttons with `disabledReason`, `prefers-reduced-motion` honoured by every animation (CSS only; no JS timers for motion).
- Lazy routes (spec §5): the eager graph is `main.tsx` → `App.tsx` → shell + stores + the Overview placeholder. Everything under `routes/` except Overview is `React.lazy`; the `build:app` budget check must list one chunk per lazy screen.
- Accessibility: palette is a `role="dialog"` with `aria-label`, input `role="combobox"` + `aria-activedescendant`, results `role="listbox"`/`role="option"`; dialogs trap focus, restore the opener (including the click-without-focus fallback), and make `#app` inert; toasts render under `<body>` outside `#app`.
- CSS Modules only; classes are never asserted in tests — behaviour tests read roles, names, `aria-*` and `data-*` attributes (`data-variant`, `data-size`, `data-tone`, `data-pulse`, `data-pressed`).
- Stores are not duplicated: no React state mirrors `session`, `live`, `stacks`, `toasts` or `unsavedChanges`; components call `useStore`.
- No new dependency; no `dangerouslySetInnerHTML`; nothing references the handoff folder (16a guards).
- Test-first, conventional commits, no code bodies in this plan.

## Review Focus

1. `?next=` must survive every path: anonymous at `/stacks/web?tab=logs` lands on `/login?next=%2Fstacks%2Fweb%3Ftab%3Dlogs`; a stream 401 followed by a late API 401 keeps `next`; logout never carries `next`; `/login?next=//evil` resolves to `/`. (Task 5.)
2. Focus discipline: a `?tab=` change leaves focus where it is; a page that focused its own control keeps it; a lazy screen gets its `h1` focused once Suspense resolves; first load leaves focus on `body`. (Task 5.)
3. Dialog: opener restored after a click that never took focus (commit 56c8aa6's case); Escape closes only the topmost of two dialogs and ignores an already-handled keydown; toasts stay clickable while `#app` is inert. (Task 2, Task 3.)
4. Palette on a disabled lifecycle (`compose unavailable`, Docker down, stack busy) shows the reason as the entry hint and never calls `api.act`; `⌘K` opens from inside a text input; Escape closes the palette without reaching an underlying dialog. (Task 6.)
5. Budget: `npm run build:app` entry contains `react`, `react-dom`, `react-router`, the shell, the stores and the Overview placeholder only; every other screen is a separate chunk; the entry is under 120 KiB gz with margin recorded in the PR. (Task 7.)
