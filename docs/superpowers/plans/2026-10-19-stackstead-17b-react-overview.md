# Stackstead Plan 17b — React overview (b): the Stacks overview screen (`/`)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Plan format:** tasks, names, signatures, test cases and examples only; no code bodies. Implementers write everything test-first.

**Goal:** Replace the eager Overview placeholder with the Evolve v2 Stacks overview: the status panel (label, sentence, sub-line, Import / New stack, stack towers, host stats strip), issue cards, the grouped stacks list with filter, ports as links, sparklines and lifecycle actions, and the side column (Activity feed, Top CPU) — pixel-accurate to the README, with every behaviour `StackList.test.ts` and `dashboard.test.ts` pin today surviving as `.test.tsx` cases, and the React entry at or under 115 kB gz.

**Architecture:** `web/src/app/routes/Overview.tsx` stays the one eager screen and only composes: it reads `stacks`, `live`, `events`, `host`, `hostHistory` and `runningOps` through `useStore`, starts the dashboard controller through `useDashboard()`, owns the one piece of screen state (`query`), and renders `web/src/app/overview/{StatusPanel,StackTowers,HostStats,IssueCards,StacksList,StackRow,SideColumn,ActivityFeed,TopConsumers}.tsx`. All view logic is the 17a pure modules; all fetch logic is the 17a stores. Lifecycle requests go through one `useStackAction()` hook shared by rows and cards. Layout under 760px is CSS-only (`@media (max-width: 759px)` in the modules), so one DOM serves both and jsdom tests assert the desktop set.

**Tech Stack:** React 19.3.1, react-router 8.4.0 (`Link`, `useNavigate`), CSS Modules, Vitest + jsdom + @testing-library/react + user-event, TypeScript strict. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-stackstead-react-evolve-v2-design.md` §2 goals 1–3, §4 anti-goals (budget, reduced motion), §5 (overview eager, entry budget), §6.3 (CSS Modules, tokens), §6.4 (tests ported before components), §8 "Issue cards", §9 row 17. README "1. Stacks overview (/)" including the mobile row, "Identity elements" (LED, stack towers, service cells), "Motion", "State". Rulings: `.superpowers/sdd/rulings-cross-plan.md` lines 6 and 8. **Depends on Plan 17a** (same branch): `hostHistory`, `createDashboard` with `storage`, `runningOps`, `overview.ts`, `issues.ts`, `hostStats`.

## Spec divergences

17a's twelve divergences apply (sparklines from the 30 s summary poll, last event from the events store, stack-level actions with honest labels, banner kinds excluded, storage card at any positive reclaimable, stack-count label, alert-derived sub-line, no log-line box, groups instead of chips, two PRs). Screen-level additions, scored with the `typesafe-ai` skill where a call was made:

1. **The h1 is the status sentence** (Jev 0.86), as designed; `App.test.tsx` cases that only wait for the overview switch from `findByRole('heading', { name: 'Stacks' })` to `findByRole('heading', { level: 1 })`. The breadcrumb, nav item, mobile title and `document.title` (`Stacks · Stackstead`, from the route table) still say Stacks.
2. **Row actions are the contextual Up-or-Restart icon button plus Logs** (Jev 0.71 that dropping the inline Down is acceptable). Down stays on the stack detail. The Svelte `Down alpha` assertions are ported against `Restart alpha` with the same expectations.
3. **Mobile layout is CSS-only** (Jev 0.91): the desktop cells get `display: none` under 760px and the mobile `cpu · mem` column the reverse; towers scroll horizontally; the host strip is two columns; the Import / New stack buttons are hidden under 760px as in the prototype (the mobile top bar's `+` is New stack; Import is in the palette's Go to group and the empty state).
4. **Status (LED) is announced as hidden text** in the first cell (`running`, `partial`, …) so the `getByText('<status>')` assertions and screen readers keep the status; the LED itself is `aria-hidden`.
5. **The Activity feed keeps today's `HH:MM:SS` clock** (tests pin zero-padded 24 h) instead of the prototype's relative ages, and keeps today's `Waiting for events…` text; the `live` / `reconnecting` pill is kept.
6. **Top CPU keeps the CPU / Memory `Segmented` toggle** (tests pin it) and its heading follows the metric (`Top CPU` / `Top memory`).
7. **Empty issue cards render nothing** (no `No alerts.` text): the status panel's `all running` label is the empty state. `No samples yet.` stays for Top CPU once the summary has loaded.
8. **Empty list state**: with zero stacks and no error the status panel reads `No stacks yet` and the list card is replaced by `EmptyState` titled `Create your first stack` with the `New stack` and `Import` links; host strip and side column still render.
9. **Budget**: everything is eager first; a measured gate in Task 4 splits the side column into a lazy chunk (the `PaletteHost` pattern) only if the entry exceeds 110 kB gz (Jev 0.96).
10. **Net RX / TX column is dropped** (not in the design); the figures stay on the stack detail.

## Global Constraints

- Behaviour parity with `StackList.svelte` and the dashboard cards: loading spinner, first-load failure banner with a busy `Retry`, degraded note when every stack is unknown, empty state with links, search by name / project / path, no-match text only for a non-empty query, `imported` tag for `external` origin, ports with `+N` and a full title, per-row running-operation spinner, lifecycle buttons soft-disabled through `lifecycleDisabledReason` (compose, Docker, parse, busy), one request per double click, success navigates to `/stacks/<name>?tab=operations&op=<id>` and calls `refreshRunningOps()`, 409 → warning toast, other failures → danger toast `Could not run <action>: <message>`, 503 → `refreshStatus()`, names encoded in every href, table semantics (`table`, `rowgroup`, `row`, `columnheader`, `cell`) under a CSS grid, the list refreshes from the stacks store on change events (no fetch in components).
- Stores are not duplicated: no React state mirrors `stacks`, `live`, `events`, `host`, `runningOps` or the controller's stores; the only screen state is `query` (README "State" lists nothing else for this screen) and the per-request `acting` set inside `useStackAction`.
- Eagerness: `Overview.tsx` and everything under `app/overview/` are in the entry; no `React.lazy` inside the screen unless Task 4's gate fires; CodeMirror and uPlot are never imported here.
- CSS Modules with tokens only; motion in module keyframes (`fadeUp` .22 s for the page, tower hover lift .15 s, bar `width .6s ease`, LED pulse through `Led`), all neutralised by the 16a `prefers-reduced-motion` rule; classes never asserted in tests — roles, names, `aria-*`, `data-*` (`data-tone`, `data-pulse`, `data-group`, `data-block`, `data-bar`).
- Accessibility: one `h1`; card titles are `h2`; the list is `role="table"` labelled by its `Stacks` heading; rows are reachable by their name link; the search input is `aria-label="Search stacks"`; every clickable target ≥ 40px under 760px; towers are buttons with a `title` and the stack name as their text.
- Entry size: `npm run build:app` after every task, the `bundle: entry …` line recorded in the task report; ≤ 115 kB gz at the end of every task; the React shape test in `bundle.test.ts` stays green.
- Test-first, conventional commits, no code bodies in this plan.

## Review Focus

1. Lifecycle safety: neither a row button nor an issue-card action calls `api.act` when `lifecycleDisabledReason` returns a reason, the reason is readable as the button's `title`, a double click sends one request, and a busy stack (from `runningOps`) disables its row and its cards at once. (Task 2, Task 3.)
2. No duplicate polling from the screen: with the App mounted at `/`, `GET /api/host` is requested once at mount and `GET /api/operations?state=running` is driven by the shared store only; `GET /api/alerts`, `/api/metrics/summary` and `/api/storage` are requested once each at mount and stop when the overview unmounts. (Task 1, Task 4.)
3. Row click vs inner links: clicking a row's empty area navigates to the stack; clicking a port link, the name link, the action button or Logs does not trigger the row navigation, and a port link opens in a new tab with `rel="noreferrer"`. (Task 2.)
4. States: first-load failure shows the banner and `Retry` only (no table, no issue cards, host strip may show); all-unknown shows the degraded note; zero stacks shows the empty state plus host strip and side column; issue cards and the Top CPU empty text appear only after their fetches resolve. (Task 1, Task 3, Task 4.)
5. Budget and eagerness: `Overview` and `app/overview/*` are in the entry; `npm run build:app` entry ≤ 115 kB gz; the bundle shape test still lists every lazy screen and the palette; if the Task 4 gate fires, `SideColumn` joins `lazyNames` and the entry drops below 110 kB. (Task 4.)
