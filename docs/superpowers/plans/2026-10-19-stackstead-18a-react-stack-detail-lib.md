**Goal:** Land everything the Stack detail screen (`/stacks/:name`, Plans 18b–18e) needs below the component layer, in `web/src/lib`, with the Svelte app still shipping and green: pure derivations for the 60-minute health timeline, the `?tab=` / `?service=` / `?op=` location resolver, the log console's level filter / search / height persistence, the compose-text helpers for the Config tab; one shared **operation tracker** store that turns every pending "in-flight" toast into a success or failure toast when the operation ends (closing the 16b ruling for the palette); and a framework-free **stack detail controller** ported from `StackDetail.svelte`'s script (load / refetch / operations / removal / remove-service state machine) so the React page only renders. Plans 18b–18e then only add components.

**Architecture:** Four pure modules (`lib/stacks/timeline.ts`, `lib/stacks/detailLocation.ts`, `lib/stacks/console.ts`, `lib/stacks/composeText.ts`) take plain values and return plain values. `lib/stores/operationTracker.ts` is a session-scoped store started in `App.tsx` next to `runningOps`: `trackOperation(op)` pushes the pending toast and remembers its id; the tracker watches the `runningOps` store and, whenever a tracked id is absent from the running list, fetches `GET /api/operations/{id}` and patches the toast through `toasts.update`. `lib/stacks/detail.ts` exports `createStackDetail(name, deps)`: the `$lib/store`-based controller holding `detail`, `operations`, `health`, `compose`, `removing` and `acting`, with the same sequence guards, debounced refetch on this project's change events, 404-after-remove handling and the remove-service conflict flow the Svelte page pins today. Nothing in this plan imports React except the three one-line wirings (`App.tsx`, `CommandPalette.tsx`, `useStackAction.ts`).

**Tech Stack:** TypeScript strict, `$lib/store`, Vitest (Node + jsdom for the two wiring tests), `installFakeFetch` / `installFakeStream` from `web/src/vitest-setup.ts`, fake timers. No new dependencies. React 19.3.1 only in the wiring edits.

## Spec divergences

Decisions scored with the TypeSafe `typesafe-ai` skill (Jev, `jev-latest`); the chosen option and its probability are recorded so reviewers can disagree with the premise rather than the outcome. These twenty calls bind Plans 18a–18e; the later plans reference them by number.

1. **Timeline data flow** (Jev 0.97): `GET /api/stacks/{name}/health?span=60m` is fetched once when the detail loads and refetched through the page's existing debounced refetch (this project's change events, flushed on resync); the last run of every service is extended to `now` at render; a 60 s timer, armed only while the tab is visible, re-renders without fetching so the window keeps sliding. No polling.
2. **Timeline rendering**: states map per spec §8 (`healthy`/`running` → success, `starting`/`restarting` → warning "restart", `unhealthy` → danger, `exited`/`removed` → down, `nodata` → outline); a service of the stack that the response omits is one `nodata` run over the whole window; no response yet (or a failed fetch) renders every lane as `nodata`; tooltip `"<state> · <n> min"` with `n = max(1, round(seconds / 60))` and `nodata` worded `no data`; the lane shows the service's restart count as a mono aux `↻ <n>` (title `restarted <n> times in the last 60 min`) when it is above zero — Jev scored this 0.48, a coin flip; controller ruling: show it, because the user's own words for the feature are "how often it restarted" and a one-second restart is invisible as a bar.
3. **Console level filter reuses `lineTone`** (Jev 1.00): `Warn+` = warning or danger, `Errors` = danger, from the same `[Error]`/`ERROR`/`[Warn]`/`WARN` tokens that colour the lines.

Scrolling up never pauses (auto-scroll just stops sticking, as today).
5. **Service chips are exclusive and restart the stream** (Jev 0.93) with the server-side `?service=` filter exactly as the Svelte select did; `?service=` preselects the chip; unknown names fall back to All.

## Global Constraints

- No API change (spec §3): every fetch is an existing `api.*` method; `types.ts` is untouched.
- Svelte keeps shipping: `make ui`, `make ui-test` and `make ui-check` stay green after every task; no Svelte file changes.
- Store rules (16b): stores live in `lib`, React reads them through `useStore`; generation guards drop late responses after stop; nothing polls while the tab is hidden; a failed fetch keeps the last value.
- Pure modules take plain values and return plain values; no `Date.now()` inside (pass `now`), no DOM, no React. `console.ts`'s storage helpers take the storage object as a parameter and swallow its exceptions.
- Controller rule: `createStackDetail` performs I/O only through its `deps`; the React hook (18b) supplies the `api.*` methods, so every test here uses fakes and no `installFakeFetch` is needed for the controller.
- Entry size: `npm run build:app` is run at the end of every task and its `bundle: entry … kB gz` line recorded in the task report; the only new entry code is `operationTracker.ts` and the three wirings (expected ≤ +1.5 kB over 102.6 kB gz); `timeline.ts`, `detailLocation.ts`, `console.ts`, `composeText.ts` and `detail.ts` must not be reachable from the entry (verified by grepping the entry chunk for `createStackDetail` / `timelineLanes`).
- Test-first, conventional commits, no code bodies in this plan.

## Review Focus

1. Tracker correctness: a tracked operation that is still running is never resolved early (absent from the list → fetched → still `running` → waits), a finished one resolves exactly once with the right toast kind, responses that arrive after `stop()` or for an untracked id are ignored, and the tracker never polls while the tab is hidden. (Task 3.)
2. Timeline arithmetic: segments of every lane cover `[window start, now]` exactly with weights that sum to the window, the last run is extended to `now` only when `now` is later than its `to`, omitted services and a missing response become a single `nodata` segment, and pulses only mark a trailing danger run. (Task 1.)
3. Controller refetch semantics preserved: initial load fetches the stack, its operations and its health once; a burst of change events for this project collapses into one or two refetches of each; another project's change fetches nothing; a resync flushes at once; `operationsRefresh` ticks reload operations only; sequence guards drop late detail responses. (Task 4.)
4. The remove-service state machine is ported verbatim: double confirm sends one `DELETE`, a 409 "changed on disk" reloads and asks again with the new hash, last/missing/failed reload outcomes set the right error and disabled reason, a cancelled session's late response triggers a refetch instead of replacing the newer session, and a 404 toasts a warning and reloads. (Task 4.)
5. Budget and eagerness: the entry line moves by at most 1.5 kB and none of the five detail-only modules appear in the entry chunk; the React shape test stays green. (Task 3, Task 4.)

### Task 3: Operation tracker store and its three entry points

README "Global" toasts; rulings line 2; divergence 9. Review focus 1 and 5.

**Files:**
- Create: `web/src/lib/stores/operationTracker.ts`, `web/src/lib/stores/operationTracker.test.ts`
- Modify: `web/src/app/App.tsx` (start/stop with the session), `web/src/app/shell/CommandPalette.tsx` + `CommandPalette.test.tsx`, `web/src/app/overview/useStackAction.ts` + `web/src/app/overview/list.test.tsx`, `docs/development.md`

**Interfaces:**
- `interface TrackedOperation { id: string; stack: string; action: string }`.
- `operationToast(op: Pick<Operation, 'stack' | 'action' | 'state'> & { error?: string }): ToastInput` — pure: `running` → `{ kind: 'info', message: '<action> · <stack>', pending: true, link: { label: 'View', href: '/stacks/<encoded stack>?tab=operations&op=<encoded id>' } }` (the link is added by `trackOperation`, which has the id); `succeeded` → `{ kind: 'success', message: '<action> · <stack> succeeded', pending: false }` (default 5 s timeout); `failed` → `{ kind: 'danger', message: '<action> · <stack> failed' + (error ?
