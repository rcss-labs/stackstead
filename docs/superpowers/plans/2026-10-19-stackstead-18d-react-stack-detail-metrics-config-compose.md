> **Plan format:** tasks, names, signatures, test cases and examples only; no code bodies. Implementers write everything test-first.

**Goal:** Fill the two empty service tabs and the compose view's `Edit YAML` slot: the per-service **Metrics** tab with four uPlot charts (CPU, Memory with limit line, Network RX + TX, Disk I/O read + write) over the page's shared live stream plus 1h / 6h / 24h / 72h history; the **Config** tab showing the service's YAML sliced from the compose file; and the **compose editor** (`YamlEditor` textarea → CodeMirror swap with changed-line marks, `DiffView` unified merge view, preview / save with hash / Ctrl+S / 409 reload-or-discard / 422 go-to-line / `.bak` toasts / Apply) behind `Edit YAML`, wired into the page's unsaved-changes guard so tab, rail, timeline and link navigation ask before discarding a dirty draft — with every `MetricsPanel`, `MetricsChart`, `ComposeEditor`, `YamlEditor` and `DiffView` behaviour and every page guard case `StackDetail.test.ts` pins ported as `.test.tsx` cases. CodeMirror and uPlot stay lazy chunks.

**Architecture:** Shared, reusable pieces go under `web/src/app/stacks/` (Plan 19's container detail and Plan 20's new-stack preview reuse them): `YamlEditor.tsx` and `DiffView.tsx` import `$lib/stacks/cm` dynamically; `MetricsChart.tsx` imports `uplot` dynamically through its default `createPlot` and takes explicit series (18a divergence 10). Detail-only pieces stay under `web/src/app/detail/`: `MetricsTab.tsx` binds `createMetricsController(name, { history, live })` to the page's `StackLiveMetrics`; `ConfigTab.tsx` renders `serviceBlock(compose, service) ?? serviceConfigYaml(…)`; `ComposeEditor.tsx` binds `createComposeEditor` and reports `dirty`; `StackDetailScreen` gains the `composeDirty` flag and the `editingCompose` state, feeds `setUnsavedChanges`, and routes every in-page navigation through `guarded()`.

**Tech Stack:** React 19.3.1, CSS Modules, Vitest + jsdom + @testing-library/react + user-event, `vi.mock('$lib/stacks/cm')` for the stubbed editor tests and the real CodeMirror for the two jsdom decoration tests, a `createPlot` fake for the chart tests. No new dependencies (CodeMirror and uPlot are already installed for Svelte).

**Spec:** spec §2 goal 1 (lazy editors and charts; unsaved-changes guard), §4 (a lost guard or an eager CodeMirror / uPlot is a failure), §5 budgets, §6.3, §6.4; README right pane (Metrics = 4 charts, Config = service YAML, Compose file + Edit YAML → existing ComposeEditor with diff / merge), "Motion" (tab content fadeUp .18 s). **Depends on 18a** (`serviceBlock`, `serviceConfigYaml`, `composeFileName`, `backupName`), **18b** (`ServicePane.children`, `ComposeView.editSlot`, `useLiveMetrics`, `guarded`) and **18c** (nothing functional; same branch order).

## Spec divergences

18a's divergences 10, 12, 15, 18 apply. Additions (author's calls):

1. **`MetricsChart` series shape**: `series: { label: string; service: string; metric: MetricKey; limit?: boolean }[]` replaces `services + metric + memLimit`; colours come from `serviceColorIndex(series.service, allServices)` for the first metric of a service and the next slot for a second metric on the same chart (TX, write), so RX / TX are distinguishable; the limit line keeps its dashed muted look. The `MetricsChart.test.ts` cases are ported against this shape; `allServices` is the stack's service list so colours match the console chips.
2. **Chart cards** follow the design (`--bg` card, radius 9, title row `<label> · <range>` with the latest value in mono on the right, 80px plot); the `Show as table` details and the `role="img"` summary stay for accessibility; the per-range buttons are a `Segmented label="Range"` in the tab's toolbar; `sampled every N s · retention H h` and `Live: <status>` stay in the toolbar.
3. **Metrics tab scope**: the controller is created per selected service (keyed), `services` filtered to the one service; the tab's empty state `No samples yet` + `The sampler records every 10 s.` and the two banners (`Metrics are not being recorded …`, `Could not load metric history`) are kept.
4. **Config tab** is read-only (`pre`, mono 12px / 1.6) with a `Edit YAML` secondary button that opens the compose editor at the stack's compose item (`guarded(() => go(itemHref(compose)))` then `editingCompose = true`); a missing block falls back to the formatter with a muted note `Shown from the parsed configuration; the file's own text could not be isolated.`
5. **Edit mode is local state**: `editingCompose` is not in the URL; `?tab=compose` opens the read view (18b), `Edit YAML` enters the editor, a parse error enters it directly (today's raw-only behaviour, so the ported `a parse error switches to raw-only mode` case finds the textbox without a click); leaving the compose item (through the guard) exits edit mode and clears the dirty flag.
6. **Guard parity**: the page keeps today's local `Discard unsaved changes?` dialog for in-page navigation (tabs, rail, chips, timeline, service Logs) and relies on the App's click-capture for links and the palette / toasts; `window.history` back / forward is not guarded (16b divergence 1); `beforeunload` is guarded by the editor while dirty.

- Metrics tab and rail share the page's one live stream (`useLiveMetrics`, 18b); the tab never opens its own; the controller is closed on unmount and when the selected service changes.
- CSS Modules with tokens; `fadeUp` .18 s on tab content; classes never asserted (`data-tone`, `data-kind`, `data-testid` where the Svelte tests used one: `diff-view`, `chart-total`, `compose-error`).
- Eagerness: nothing new in the entry; entry line recorded per task, unchanged.
- Test-first, conventional commits, no code bodies in this plan.

## Review Focus

1. Guard behaviour: a dirty draft asks before a tab, rail, chip or timeline navigation and before a link click, stays when cancelled, leaves and clears when confirmed; a clean editor never asks; browser back away from a dirty editor leaves no stale flag; the `beforeunload` prompt is armed only while dirty. (Task 2.)
2. Save safety: `PUT` carries `{ content, hash }` of the loaded file; a 409 never overwrites (Reload keeps the draft and re-previews with the new hash, Discard drops it); Ctrl+S is ignored during a conflict; typing during a save is kept and the editor stays dirty; a 422 shows the message verbatim in a `pre` and moves the cursor to the line. (Task 2.)
3. Lazy editor correctness: the textarea works synchronously before the chunk, focus survives the swap, a chunk resolving after unmount creates nothing, readonly toggles reach CodeMirror without recreation, changed lines are marked 150 ms after an edit against `original`, and the diff view destroys on unmount. (Task 1.)
4. Chart lifecycle: one plot per structure, data updates in place, resize observed, destroy on unmount (also for a plot that finishes creating after unmount), no stacked plots when the structure changes before load, theme change rebuilds, `Chart unavailable` keeps the table. (Task 3.)
5. Budget and shape: `cm` and `uplot` are lazy chunks, the entry line is unchanged, and the shape test lists them. (Task 3.)
