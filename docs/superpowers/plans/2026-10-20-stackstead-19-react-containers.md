# Stackstead Plan 19 — React containers: list with inline log peek and j/k/↵/r/Esc keys, ContainerDetail restyle

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Plan format:** tasks, names, signatures, test cases and examples only; no code bodies. Implementers write everything test-first.

**Goal:** Replace the Svelte `ContainerList` and `ContainerDetail` routes with the Evolve v2 Containers screen — H1 with `<n> · <running> running` and the desktop key hints, the All / Running / Stopped / Problems / Unmanaged chips with mono counts, the problems-first table (LED · name · stack · image · state tag + health · ports · CPU · Memory · ↻ 24h), a keyboard-focused row ring, an inline **log peek** row (`--chassis`, `fadeUp` .18 s, "streaming" dot, status, today's actions, `Open full logs`, the last 8 lines streaming live with ERROR / WARN tones and the line flash; one open at a time; closing releases the stream) driven by click / tap and by `j` `k` `↵` `r` `Esc` — plus the `ContainerDetail` page restyled with the new tokens and identity elements while keeping every behaviour `ContainerDetail.test.ts` pins (name resolution, recreation, refetch rules, logs tab through the shared `LogConsole`).

**Architecture:** Everything new lives under `web/src/app/containers/`; the two route files in `web/src/app/routes/` stay thin wrappers so `routes.tsx` and the lazy chunk names (`ContainerList`, `ContainerDetail`) are untouched. Data comes from the unchanged `lib/containers/list.ts` controller (`createContainerList` over `createRefreshList`: 10 s visible refetch, 300 ms debounced change refetch, `patch` / `refresh`) bound through one hook, `useContainerList()`. Container actions (start / stop / restart with their confirmations, reasons, in-flight set and toasts) move from the Svelte `ContainerActions` component into one hook, `useContainerAction()`, so the row buttons, the peek header, the detail header **and the `r` key** share one state machine and one `ConfirmDialog` per page. The peek streams through `useLogStream({ kind: 'container', id }, { tail: 8, follow: true })` (18c) and renders its own two-column lines; the detail's Logs tab reuses `LogConsole` (18c) with a container source. Keys are one `window` keydown hook with explicit ignore rules; `j` / `k` move real DOM focus along a roving-tabindex row list.

**Tech Stack:** React 19.3.1, React Router 8.4.0, CSS Modules, Vitest + jsdom + @testing-library/react + user-event, `installFakeFetch`, `installFakeStream`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-stackstead-react-evolve-v2-design.md` — §2 goal 1 (parity: routes, `?tab=`, titles, focus, a11y, reduced motion) and goal 3 ("containers with streaming inline log peek and j/k/↵/r/Esc keys"), §3 (`ContainerDetail` keeps today's behaviour, restyled), §4 (no SSE drop / duplicate, budget, reduced motion), §5 (entry budget, route-level lazy), §6.1 (controllers reused through `useStore`), §6.3, §6.4, §8 "Inline peek" (`GET /api/containers/{id}/logs`, same buffer, last 8 lines, one open at a time, closing releases the stream), §9 row 19. ## Spec divergences (author's calls, reviewable)

1. **Row controls move into the peek.** The design's rows carry no buttons or Logs link. Today's per-row `Logs` link and Stop / Start / Restart icon buttons are rendered in the peek header instead (`Open full logs` → `/containers/<name>?tab=logs`; `ContainerActions` at `md` size, or `Manage in stack →` for stack-managed containers). The name link to the detail stays on the row.
2. **`r` and the peek's Restart follow today's rules.** A stack-managed container has no Restart (the API answers 409 "manage it there"), so the peek shows `Manage in stack →` and `r` is a no-op on that row; Docker unreachable and an in-flight action soft-disable exactly as `ContainerActions.test.ts` pins. Container actions are not operations (no id to track), so the operation tracker is not involved; the success toasts stay `<name> started | stopped | restarted`.
3. **Peek lines are their own small renderer**, not `LogLines`: the design's grid is `62px minmax(0,1fr)` (no service column, no pin, no search, no notices), bounded to the last 8 lines, `max-height: 150px`, stuck to the bottom. The stream is the shared `useLogStream` with `tail: 8`. `LogConsole` is reused on the detail's Logs tab, where the design is silent and today's viewer applies.
4. **The search box stays** (parity: searches by name, image, stack / project, ports), right of the chips on desktop and full width under them on mobile.
5. **The row drops the short id** (the design has none; the detail page shows the full id). The Docker status string (`Up 2 minutes (unhealthy)`) is shown in the peek header on desktop and as the row's sub-line on mobile, as the design does.
6. **A peek closes when its container leaves the visible list** (chip, search or removal) and its stream is released; a chip change resets `focusIndex` to 0 (as the prototype does); the list shrinking clamps `focusIndex`.
7. **LED mapping** (`containerLed` in `lib/containers/list.ts`): `isProblem` → `danger` + pulse; `health === 'starting'` or `state === 'paused'` → `warning`; `running` → `success`; otherwise `faint`.
8. **Ports** keep today's text (`portChips(ports, 2)` with `+N` and the full list as `title`), mono in `--info` as the design colours them, without host links (container port strings are not plain host ports as the overview's are).
9. **Keys are global to the page** (`window` keydown), ignored while the event target is an `input`, `textarea`, `select`, `[contenteditable]`, inside a `[role="dialog"]` / `[role="alertdialog"]`, or carries Ctrl / Meta / Alt; `Enter` is also ignored when the target is an `a` or `button` (native activation). `j` / `k` clamp at the ends and move DOM focus to the row; the key hints (`kbd`) are hidden under 760px, the keys stay active.
10. **Detail Logs tab** renders `LogConsole` (collapse, resize, persisted height under `stackstead.logsHeight`, the `container or logs no longer available` wording) open by default; `services` is empty so the chips are hidden.

## Review Focus

1. Peek stream lifetime: exactly one open; opening B aborts A's request; `Esc`, a second click, a filter that hides the row, and unmount abort it; a recreated container (same name, new id) re-opens the peek on the new id; the request carries `tail=8&follow=1` and no `service=`. (Task 3.)
2. Keyboard safety: keys never fire while typing in the search box, inside the confirm dialog or the palette, or with Ctrl / Meta / Alt; `Enter` on the name link or a button is left to the element; `r` honours stack-managed, Docker-unreachable and in-flight rules; `j` / `k` clamp and never throw on an empty list. (Task 3.)
3. Action results: the returned row is applied at once and a refetch follows without waiting for it; a 204 refetches and the row disappears; a 409 toasts a warning and changes nothing; a double click sends one request and soft-disables that row only. (Task 1, Task 2.)
4. Detail resolution: `Container not found` vs `This container no longer exists`; a new id after recreation reloads the details and remounts the log stream on the new id; a stale details response never overwrites a newer one; env / cmd / entrypoint are never rendered; the page survives a failing list refresh with the warning banner. (Task 4.)
5. Bundle shape: nothing from `app/containers/` or `LogConsole` in the eager entry; the entry line stays 104.9 kB; `ContainerList` and `ContainerDetail` are lazy chunks. (Task 5.)
