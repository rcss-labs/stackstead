## Spec divergences (author's calls, reviewable)

1. **Button and heading copy follows the design where it differs from the Svelte strings:** `+ Add another service` (Svelte: `+ Add service`), H1 `New stack`, and the lead `Writes compose.yaml into a folder named <name> in the stacks directory. Nothing is written until you confirm.` (the stacks directory path is not known to the client, so the design's absolute path is not shown). The ported tests use the new label. Everything else the Svelte tests assert is unchanged (Global Constraints).
2. **Document titles come from the route table** (`App`'s `useDocumentTitle`): `New stack · Stackstead` (Svelte: `Create stack`, which no longer matches the H1) and `Import stack · Stackstead` (`routes.tsx` title changed from `Import` to `Import stack`; the sidebar label and breadcrumb stay `Import`). The screens set no title of their own.
3. **The port check is a verdict per port row, computed in render** from the form's port strings and the containers list: `Port <n> is used by <who>` (danger; `who` = the container's `stack` when it is in a registered stack, else its `name`), `Port <n> is also published by <service> in this stack` (warning; another card, or an earlier row of the same card; `<service>` falls back to `another service`), otherwise `Port <n> is free` / `Ports <lo>-<hi> are free` (success). A range reports its first conflicting port. Protocol-aware (`/udp` only conflicts with `/udp`; default `tcp`), host-IP-agnostic (a `127.0.0.1:` binding counts as taken), silent for container-only specs (`80`), `$VAR` specs, unparsable specs, and while the containers list has not loaded or failed. It sets `data-check` on the input, never `aria-invalid`, and never blocks submit.
4. **The preview is a `<pre>`**, not `YamlEditor`: `services:` followed by each card as `serviceConfigYaml(name, fromForm(form, null))` indented two spaces, cards in order, unnamed cards as `service-<n>`, a card with no config as `<name>: {}`. It is what the server receives, rendered with today's deterministic serializer, not the file the server will write (the server may order keys differently). Derived on every render, no state, no live region.
5. **The disclosure lives in `ServiceForm`** as an optional prop: with `advanced={{ summary }}` the Environment, Networks, Network mode, Healthcheck and Resources (limits) groups render inside one `<details>`, and the Restart policy fieldset moves up to sit right after Source (the design's "Image / Build context + Restart policy" row). The disclosure is forced open while any shown error belongs to a group inside it, so `focusFirstError` always reaches its target. Without the prop the form is unchanged (stack-detail editors).
6. **Volumes get `Browse…`** when `onBrowse` is given (README: "Volumes + Browse… (FileBrowser)"): `aria-label="Browse for volume <n>"`, dir mode, and the picked path replaces the host side of the row (`./old:/data:ro` → `/srv/data:/data:ro`; an empty row becomes `/srv/data:`). `onBrowse` gains a third argument `purpose: 'context' | 'dockerfile' | 'volume'` so hosts can title the browser; the 18e panels' titles are switched to it (`Choose a build context` / `Choose a Dockerfile` / `Choose a host folder`), no other change there.
7. **Restart policy defaults to today's `Default (no restart)`**, not the prototype's `unless-stopped`: parity with `emptyForm()` and the server's behaviour wins over mock data.
8. **The unsaved-changes guard** is the shared `unsavedChanges` store (`App` owns the dialog and the link capture): the screen writes `setUnsavedChanges(isCreateDirty(state))` in an effect, clears it on unmount and right before navigating after a successful create. Dirty = a non-empty stack name, more than one card, or any card whose name (once edited) or form differs from `emptyForm()`. Import has no guard (one field; today has none either).
9. **Title polish (18e deferred):** `ListEditor`'s `title` adopts the panel-label style (mono 10.5px, uppercase, `.1em`, `--muted`) and `ServiceForm`'s legend `.title` matches it exactly, so every group heading in the form reads as one system. Style only; no behaviour test.
10. **Cards stay collapsible** as today (one `ServiceForm` mounted at a time, header button with `aria-expanded`, error marker on collapsed cards); the design's single-service card is the one-card case. The first card follows the stack name until its name is edited, as today.

### Task 1: `portCheck.ts` and `createPreview.ts` (pure)

Spec §8 "Port-conflict check"; divergences 3, 4, 8. Review focus 2 and 3.

**Files:**

**Interfaces (`portCheck.ts`):**
- `type Proto = 'tcp' | 'udp' | 'sctp'`
- `interface HostPorts { lo: number; hi: number; proto: Proto }` — the host side of a compose short-syntax spec.
- `hostPorts(spec: string): HostPorts | undefined` — mirrors `checkPort` in `lib/compose/form.ts` (`[ip:]host[-hi]:container[-hi][/proto]`, IPv6 in brackets, proto default `tcp`); `undefined` for container-only specs (`80`, `80/udp`), specs containing `$`, malformed specs, ports outside 1–65535, descending ranges, unknown protocols. Trims whitespace.
- `interface PublishedPort { port: number; proto: Proto; who: string }`
- `publishedPorts(rows: ContainerRow[]): PublishedPort[]` — parses each row's `ports` entries (`hostIP:hostPort->containerPort/proto`, IPv6 host in brackets), `who = row.stack || row.name`; entries that do not parse are skipped.
- `type PortVerdict = { tone: 'danger' | 'warning' | 'success'; text: string }`
- `portVerdict(spec: string, own: { service: string; index: number }, formPorts: { service: string; index: number; spec: string }[], published: PublishedPort[] | undefined): PortVerdict | undefined` — `undefined` when `hostPorts(spec)` is undefined or `published` is undefined; else for each port in `[lo, hi]` (in order): a `published` entry with the same port and proto → `{ tone: 'danger', text: 'Port <n> is used by <who>' }`; else another `formPorts` entry (different `service` or `index`, and listed **before** `own` in `formPorts` order) whose host range and proto cover it → `{ tone: 'warning', text: 'Port <n> is also published by <service> in this stack' }` (`<service>` = that entry's `service` or `another service` when empty); first hit wins; no hit → `{ tone: 'success', text: lo === hi ? 'Port <n> is free' : 'Ports <lo>-<hi> are free' }`. Ranges are capped at 1024 ports per spec (beyond that only `lo` is checked) so a typo cannot stall the render.

**Interfaces (`createPreview.ts`):**
- `interface PreviewCard { name: string; form: ServiceForm }`
- `previewYaml(cards: PreviewCard[]): string` — `services:` then each card: `serviceConfigYaml(name || 'service-<n>', fromForm(form, null))` with every line indented two more spaces; when the service block has only its header line, append ` {}`. Never throws for an empty or partial form (`fromForm` with `original: null` only throws for read-only fields, which a new form never has).
- `interface CreateDirtyInput { stackName: string; cards: { name: string; autoName: boolean; form: ServiceForm }[] }`
