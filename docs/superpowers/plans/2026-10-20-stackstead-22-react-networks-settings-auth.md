## Spec divergences (author's calls, reviewable)

1. **Networks is a card grid, not a table.** The README's card replaces today's `role="table"` rows; the ported tests find cards with `getAllByRole('article')` instead of rows, and the `data-label` responsive-cell assertion is dropped (cards carry visible `dt` labels). Each card is `article aria-labelledby` its `h2` name, so the list reads as a list of named regions.
2. **Attached containers are listed open on managed and unmanaged cards; built-ins keep today's toggle.** The README says "attached containers with IPs" and "built-ins shown compactly", so cards of `bridge` / `host` / `none` (any `builtin`) render the `dl` only when at least one of subnet / gateway / parent is set and fold their containers behind today's `Show containers on <name>` button (`aria-expanded`, `aria-controls`); every other card lists its containers directly, and an empty list reads `No containers attached` on every card. Today's ` → ` arrow is gone: the IP is its own mono cell (`—` when unknown).
3. **The summary sentence is computed client-side** by `networkSummary`: `<n> network(s)` (its own `span`, so `findByText('4 networks')` keeps working) followed by ` · <n> owned by stacks` (`stack` set), ` · <n> LAN network(s)` (driver `macvlan` or `ipvlan`) and ` · <n> built-in`, each part only when its count is > 0; singular forms at 1 (`1 network`, `1 LAN network`). Today has `<n> networks` only.
4. **Settings keeps today's cards and copy; only the layout and labels change.** The desktop section nav is five in-page anchor links (`#settings-system` … `#settings-account`) inside `nav aria-label="Settings sections"`, hidden under 760px; no scroll-spy and no `aria-current` (the prototype's highlight is a mock state). Card headers become 14px `h2`; the `dt`s, pills and the Theme / Density labels are panel labels (mono 10px uppercase). The status dots become `Led size={7}` with the same tones. Theme keeps today's third option `System` (the prototype shows two; `appearance.ts` has three and the rail toggle relies on it).
5. **Settings `Log out` stays today's direct `logout()`** (warning toast `Logout may not have completed on the server.` on failure), not the rail's guarded logout; under the App guard it therefore lands on `/login?next=%2Fsettings`, as the Svelte app does today. Unifying it with the rail (which needs the frame's guard) is noted for Plan 23.
6. **`/setup` never becomes a `?next=`.** `useSessionGuard` sends an anonymous user found on `/setup` to `/login` without `next` (today's Svelte Setup effect did the same from inside the screen, which React cannot do because `App` swaps the screen first). An authenticated user at `/setup` still goes to `/`, so nothing is lost.
7. **Login and Setup share `AuthCard`** (logo, wordmark `h1` with the visually hidden verb, host, footer) with today's sizes (card 360 / 400px, 28px padding, 34px controls) and 40px controls under 760px; the error line keeps the `✖ ` prefix inside `p role="alert"`. Labels are today's: `Sign in` (not the placeholder's `Log in`) and `Create account`.
8. **PasswordForm's `.error` assertions become id assertions**: CSS Modules hash the class, so the ported tests read `document.getElementById('pw-new-error')` (the `Field` error id contract) and `aria-invalid`.
